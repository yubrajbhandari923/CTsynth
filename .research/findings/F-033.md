# F-033 · PROCESS: a nondeterministic test was hiding in the suite and I committed on top of it. tests/aapm/test_unet.py::test_constraints_exact seeded its INPUT but not the network WEIGHT initialisation, and its last assertion (a linear head must emit at least one negative value) depends on random weights - it failed about 1 run in 6. I observed '1 failed, 221 passed' in a gate, committed anyway, and only caught it because the count differed from the expected 222. Fixed with torch.manual_seed(0) inside the test; verified 12/12 on the file and 8/8 on the full suite. Two lessons: (1) a gate result must be READ before committing, not assumed; (2) a test whose assertion depends on random initialisation must seed the initialisation, not only the data - our determinism tests covered training loops but not test fixtures themselves.

## Statement

PROCESS: a nondeterministic test was hiding in the suite and I committed on top of it. tests/aapm/test_unet.py::test_constraints_exact seeded its INPUT but not the network WEIGHT initialisation, and its last assertion (a linear head must emit at least one negative value) depends on random weights - it failed about 1 run in 6. I observed '1 failed, 221 passed' in a gate, committed anyway, and only caught it because the count differed from the expected 222. Fixed with torch.manual_seed(0) inside the test; verified 12/12 on the file and 8/8 on the full suite. Two lessons: (1) a gate result must be READ before committing, not assumed; (2) a test whose assertion depends on random initialisation must seed the initialisation, not only the data - our determinism tests covered training loops but not test fixtures themselves.
