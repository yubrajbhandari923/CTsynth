# F-032 · SECTION B.4 VERIFIED from the kit SOURCE CODE (not an audit summary). starting_kit/model/dualEnergyTransmission.py lines 13-20 state verbatim: 'knock out every other view for kVp switching. First view is 80 kVp, second is 50 kVp, ...' and implement it as Sinogram[:,::2] for kvp=='80' and Sinogram[:,1::2] for kvp=='50'. Our src/ctsynth/aapm/schema.py convention (KVP_HIGH=80 on EVEN views, KVP_LOW=50 on ODD views, kvp_of_view returning 80 for view%2==0) therefore matches the official generator exactly. Note projection.py itself computes a full 512-view sinogram with NO kVp split; the interlacing is applied afterwards in dualEnergyTransmission.py, so any projection-domain work must apply the parity split itself and must not assume the stored 256-view per-kVp arrays are contiguous angular sweeps - they are every other view of a 512-view circular fan-beam scan.
