# EXP-017 · Oracle forward-model verification on AAPM kit cases

## Hypothesis

Ground-truth maps through the fan-beam polychromatic model reproduce kit transmissions to float32/discretisation level

## Motivation


## Method

projects/p05_aapm/exp017_oracle.py on GPU. Cases: the 10 starting-kit cases (dataset indices found by hash; kit sinograms give a projector-only check) + 40 evenly spaced other training cases. Ground-truth fractions -> AapmFanbeamForward (float32 and float64 on 3 cases) -> compared with the dataset's lowkVp/highkVpTransmission. Secondary, no pass/fail: exact-chord vs kit-layered projector discrepancy at 128^2 and 64^2 (reduced geometry, same fov/R/SDD).

## Expected outcome

Max error ratio well below 1 (observed dev check: kit sinogram max abs diff 2.9e-6 cm on one case, not used to set the tolerance). Exact-chord differs from kit projector by a discretisation term that shrinks with resolution.

## Success criteria

PRIMARY (pre-derived, independent of observed errors): for every ray of every case and both kVp, |T_pred - T_ref| <= tol_T(ray) = 4*sum_m S_m*dP_m + sqrt(E)*2^-23*T, with S_m = sum_E 0.5 s_E mu_mE exp(-sum mu P) (first-order sensitivity of T to path length) and dP_m = sqrt(2*512)*2^-24*P_m (random-walk float32 accumulation over 512 layers x 2 weights). Pass = max ratio |err|/tol_T <= 1 with zero violating rays. Projector-only check on kit cases: |P - kit Sinogram| <= 4*sqrt(1024)*2^-24*P_max. Finite outputs, T in (0,1]. Report RMSE, MAE, max abs, log-T RMSE, relative error where T>1e-3, profiles by view angle / detector bin / tissue-vs-air rays, float32-vs-float64 difference, runtime and peak GPU memory. STATEMENT: agreement establishes implementation fidelity to the official generator under a shared model, not scanner accuracy.

## Stop conditions

Any violating ray, nonfinite value or T outside (0,1]: stop; diagnose geometry/parity/table conventions before EXP-018+ or any physics-loss training.
